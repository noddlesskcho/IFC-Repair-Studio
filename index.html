      Missing geometry context (ContextOfItems)

      What is wrongEach shape in an IFC file must say which view it belongs to: the 3D model (Body) or the 2D plan outline (FootPrint). These shapes are missing that link, so the portal's IFC schema check rejects the file with error IFC0000104: IfcShapeRepresentation.ContextOfItems is required.

      What the repair doesIt adds the missing link to the model's only matching context. Nothing is deleted and no shape is changed, so no check in the source model is needed. A row marked "(type)" is a type object: the fix applies to every placed instance of that type.

      Areas without geometry (IfcSpace): fix these in the source model

      What is wrongThese IfcSpace objects (rooms, spaces and areas) were exported with no shape at all (Representation = $).

      Why they have no geometryThe Why no geometry column reads the area and height exported for each space (Qto_SpaceBaseQuantities). Has area, but no 3D shape was exported means the room is placed and enclosed, but its boundary could not be turned into a 3D shape, usually because of very short or overlapping boundary lines, thin slivers or narrow gaps. Area is 0 means it is not enclosed or is redundant.

      Why the tool does not change themThe IFC file has no correct outline for these spaces, so there is no shape to add. They stay unchanged in the repaired IFC. This is a report only.

      What you should doDownload the areas report. For each row, find the room or area in your authoring software by its element ID or GUID (in Revit: Manage › Select by ID), and fix it as the report says. Then export the IFC again.
